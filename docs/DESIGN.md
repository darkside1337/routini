# 📐 Design Brief & UI Specification

**Project:** Routini  
**Surface:** Goal Creation & AI Habit Selection Flow  
**File Reference:** [`components/create-goal-modal/`](../components/create-goal-modal/)  

---

## 1. Job & Audience

* **User & Context:** A goal-oriented individual looking to establish actionable routines without the cognitive friction of manual habit breakdown. Arrives with a high-level intention (e.g., *"Learn TypeScript"*, *"Run 5k marathon"*).
* **Visitor Mode:** **Operate** — swift, focused, low visual noise, with high task completion momentum.

---

## 2. Outcome & Product Truth

* **Primary Task:** Convert a high-level goal into 3–5 realistic daily habits generated by AI, lock/pin desirable ones, re-roll the rest if needed, and commit them directly to the dashboard.
* **Product-Specific Truth:** Routini removes the intimidation of blank habit trackers by using AI to generate precise, bite-sized routines that can be locked or re-rolled in seconds.

---

## 3. Structural Topology & Interaction Model

A compact, two-stage modal dialog (`Dialog`):

```
+-------------------------------------------------------------+
| Stage 1: Goal Prompt                                        |
|                                                             |
| [ Goal Name: e.g. "Run 5k marathon"                       ] |
| [ Context / Nuance: "Morning runs, under 30 mins..."     ] |
|                                                             |
|                                        [ Generate Habits ->]|
+-------------------------------------------------------------+
                              |
                              v  (Shimmer Skeletons + Phase Captions)
+-------------------------------------------------------------+
| Stage 2: Habit Review & Lock Board                          |
| Goal Context: "Run 5k marathon"                             |
|                                                             |
| +---------------------------------------------------------+ |
| | [🔒 Locked] 15-min Morning Zone 2 Jog (Daily, 15m)      | |
| +---------------------------------------------------------+ |
| | [🔓 Unlocked] Dynamic Warmup & Ankle Drills (Daily, 5m) | |
| +---------------------------------------------------------+ |
| | [🔓 Unlocked] Post-run Hydration + Log (Daily, 5m)      | |
| +---------------------------------------------------------+ |
|                                                             |
| [< Back]               [🔄 Re-roll Unlocked]  [Save Habits] |
+-------------------------------------------------------------+
```

### 3.1 Stage 1 (Goal Prompt)
* Direct input field with contextual placeholder examples and optional nuance textarea.
* Single primary CTA triggers generation with keyboard submission (`Enter`).

### 3.2 Stage 2 (Habit Review & Lock Board)
* Clean vertical stack of selectable habit cards with instant Lock/Unlock toggle.
* Locked items stay fixed while unlocked slots re-roll upon requesting regeneration.

### 3.3 Focal Moment
* The generation loading state featuring shimmering card skeletons with contextual step status indicators:
  > *"Analyzing goal..."* → *"Drafting actionable daily routines..."* → *"Finalizing habit stack..."*
* Followed immediately by lock-and-commit capability.

### 4.2 In Scope
* Two-step modal transitions with preserved state.
* Habit locking/unlocking affordances with distinct active/inactive visual states.
* Re-roll mechanism for unlocked habits only.
* Skeleton loading states with progress messaging.
* Clean toast notification + auto-close on save.

### 4.3 Explicit Anti-Goals
* ❌ No complex multi-day custom scheduler in this modal (keep it swift and lightweight).
* ❌ No multi-step nested modals or gamified confetti popups.

---

## 5. States & Data Ranges

* **Card Count:** 3 to 5 generated habits per goal.
* **Component States:**
  1. **Initial Form State:** Empty, valid, error validation.
  2. **Generating State:** Skeletons with smart status caption.
  3. **Review State:** Mixed locked / unlocked cards.
  4. **Regenerating State:** Locked cards frozen/disabled, unlocked cards showing active shimmer skeletons.
  5. **Saving State:** Disabled actions with loading spinner on primary CTA.
  6. **Success State:** Toast notification, modal dismiss, dashboard focus.

---

## 6. Interaction & Layout Mechanics

* **Hierarchy:** Modal Header (Goal summary context) → Habit card stack → Sticky action bar (`Back`, `Re-roll Unlocked`, `Save Habits`).
* **Affordances:** Clear padlock icon toggle on habit cards:
  * *Unlocked:* Hover reveal on unlocked cards, subtle border.
  * *Locked:* Solid primary indicator, distinct accent border, high-contrast lock badge.
* **Keyboard & A11y:**
  * Full focus trapping within dialog.
  * `Enter` to submit in prompt field.
  * `Space` or `Enter` to toggle habit lock on focused cards.
  * `Escape` to dismiss modal.

---

## 7. Tech Stack & Implementation Constraints

* **Framework:** Next.js 15 App Router, React 19.
* **Styling & UI Components:** Tailwind CSS + shadcn/ui components (`Dialog`, `Button`, `Field`, `Input`, `Textarea`, `Skeleton`).
* **Server Actions:**
  * `generateHabits(goal, nuance)`
  * `regenerateHabits(goal, lockedHabits)`
  * `saveHabits(goalData, habits)`
* **Toasts:** Sonner.
